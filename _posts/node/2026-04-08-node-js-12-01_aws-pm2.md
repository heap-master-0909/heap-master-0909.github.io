## PM2란?

PM2(Process Manager 2)는 Node.js 애플리케이션을 **프로덕션 환경**에서 운영하기 위한 프로세스 매니저이다. 서버에서 `node app.js`로 직접 실행하면 에러 발생 시 프로세스가 종료되고, 터미널을 닫으면 앱도 꺼진다. PM2는 이런 문제를 해결해 준다.

### PM2의 핵심 기능

| 기능 | 설명 |
|:---|:---|
| 프로세스 관리 | 앱 시작, 중지, 재시작, 삭제 |
| 자동 재시작 | 에러로 크래시 나면 자동으로 다시 실행 |
| 클러스터 모드 | CPU 코어 수만큼 프로세스를 띄워 성능 향상 |
| 로그 관리 | stdout/stderr 로그를 파일로 자동 저장 |
| 모니터링 | CPU, 메모리 사용량 실시간 확인 |
| 무중단 배포 | 서비스 중단 없이 코드 업데이트 가능 |

### 설치

```sh
npm i -g pm2
```

글로벌로 설치해야 어디서든 `pm2` 명령어를 사용할 수 있다.

### 기본 명령어

```sh
# 앱 시작
pm2 start app.js

# 앱 이름 지정하여 시작
pm2 start app.js --name "my-app"

# 실행 중인 프로세스 목록 확인
pm2 list

# 특정 프로세스 중지
pm2 stop my-app

# 특정 프로세스 재시작
pm2 restart my-app

# 특정 프로세스 삭제
pm2 delete my-app

# 모든 프로세스 중지
pm2 stop all

# 모든 프로세스 삭제
pm2 delete all
```

### 실시간 모니터링

```sh
# 대시보드 형태의 모니터링
pm2 monit

# 로그 실시간 확인
pm2 logs

# 특정 앱 로그만 확인
pm2 logs my-app

# 최근 200줄 로그 확인
pm2 logs --lines 200
```

### 클러스터 모드

Node.js는 기본적으로 싱글 스레드이다. 서버 CPU가 4코어인데 프로세스 1개만 돌리면 나머지 3코어는 놀게 된다. 클러스터 모드는 여러 프로세스를 띄워 모든 코어를 활용한다.

```sh
# CPU 코어 수만큼 프로세스 생성
pm2 start app.js -i max

# 프로세스 수 직접 지정
pm2 start app.js -i 4

# 코어 수 - 1개 (OS용 코어 확보)
pm2 start app.js -i -1
```

| 옵션 | 의미 |
|:---|:---|
| `-i max` | 사용 가능한 모든 CPU 코어 사용 |
| `-i 4` | 4개의 프로세스 생성 |
| `-i -1` | 전체 코어 수 - 1개 사용 |

클러스터 모드에서는 PM2가 자동으로 **로드 밸런싱**을 해 주므로, 들어오는 요청이 여러 프로세스에 골고루 분산된다.

### 무중단 재시작 (Zero-Downtime Reload)

```sh
pm2 reload my-app
```

`restart`와 `reload`의 차이:

| 명령어 | 동작 방식 | 다운타임 |
|:---|:---|:---|
| `pm2 restart` | 모든 프로세스를 한 번에 종료 후 재시작 | 있음 |
| `pm2 reload` | 프로세스를 하나씩 순차적으로 교체 | 없음 |

`reload`는 클러스터 모드에서만 사용 가능하다. 프로세스 A가 요청을 처리하는 동안 프로세스 B를 새 코드로 교체하고, B가 준비되면 A를 교체하는 방식이다.

### ecosystem 설정 파일

매번 명령어에 옵션을 붙이는 대신, 설정 파일로 관리할 수 있다.

```sh
# 설정 파일 생성
pm2 ecosystem
```

`ecosystem.config.js` 파일이 생성된다:

```js
module.exports = {
  apps: [{
    name: 'my-app',
    script: './app.js',
    instances: 'max',
    exec_mode: 'cluster',
    env: {
      NODE_ENV: 'production',
      PORT: 3000,
    },
  }],
};
```

| 속성 | 설명 |
|:---|:---|
| `name` | 프로세스 이름 |
| `script` | 실행할 스크립트 경로 |
| `instances` | 프로세스 수 (`max`이면 코어 수만큼) |
| `exec_mode` | 실행 모드 (`fork` 또는 `cluster`) |
| `env` | 환경 변수 설정 |

설정 파일로 실행:

```sh
pm2 start ecosystem.config.js
```

### 서버 재부팅 시 자동 시작

AWS EC2 인스턴스가 재부팅되면 PM2 프로세스도 다시 띄워야 한다. `startup` 명령어로 자동화할 수 있다.

```sh
# 현재 실행 중인 프로세스 목록 저장
pm2 save

# 시스템 부팅 시 PM2 자동 실행 등록
pm2 startup

# 출력된 명령어를 복사하여 실행 (sudo 권한 필요)
# 예: sudo env PATH=$PATH:/usr/bin pm2 startup systemd -u ubuntu --hp /home/ubuntu
```

순서가 중요하다:

1. 앱을 `pm2 start`로 실행
2. `pm2 save`로 현재 프로세스 목록 저장
3. `pm2 startup`으로 부팅 시 자동 실행 등록

### PM2 + Express 실전 예시

AWS EC2에서 Express 앱을 PM2로 운영하는 흐름:

```sh
# 1. 프로젝트 클론
git clone https://github.com/user/my-app.git
cd my-app

# 2. 의존성 설치
npm ci --production

# 3. PM2로 클러스터 모드 시작
pm2 start app.js --name "my-app" -i max

# 4. 상태 확인
pm2 list

# 5. 부팅 시 자동 시작 설정
pm2 save
pm2 startup
```

코드 업데이트 시:

```sh
git pull origin main
npm ci --production
pm2 reload my-app
```

`pm2 reload`를 사용하면 서비스 중단 없이 새 코드가 반영된다.

### 유용한 명령어 모음

| 명령어 | 설명 |
|:---|:---|
| `pm2 list` | 실행 중인 프로세스 목록 |
| `pm2 show my-app` | 특정 앱의 상세 정보 |
| `pm2 monit` | 실시간 모니터링 대시보드 |
| `pm2 logs` | 전체 로그 확인 |
| `pm2 flush` | 로그 파일 비우기 |
| `pm2 reload all` | 모든 앱 무중단 재시작 |
| `pm2 save` | 현재 프로세스 목록 저장 |
| `pm2 resurrect` | 저장된 프로세스 목록 복원 |
| `pm2 update` | PM2 데몬 업데이트 |

### node app.js vs pm2 비교

| 항목 | `node app.js` | `pm2 start app.js` |
|:---|:---|:---|
| 에러 시 | 프로세스 종료, 서비스 중단 | 자동 재시작 |
| 터미널 종료 시 | 앱도 종료 | 백그라운드에서 계속 실행 |
| 멀티코어 활용 | 불가 (싱글 프로세스) | 클러스터 모드로 활용 가능 |
| 로그 관리 | 콘솔에만 출력 | 파일로 자동 저장 |
| 모니터링 | 없음 | CPU/메모리 실시간 확인 |
| 배포 | 서비스 중단 필요 | 무중단 배포 가능 |
