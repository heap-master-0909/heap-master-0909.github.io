> HTTP는 **무상태(Stateless)** 프로토콜이다. 서버는 이전 요청을 기억하지 못하므로, 클라이언트를 식별하려면 별도의 수단이 필요하다. **쿠키(Cookie)**는 이 문제를 해결하기 위해 브라우저에 저장되는 작은 데이터 조각이다.

## 쿠키란?

쿠키는 **서버가 클라이언트(브라우저)에 저장하도록 보내는 작은 문자열 데이터**다. 브라우저는 이후 같은 서버에 요청할 때마다 저장된 쿠키를 자동으로 함께 전송한다.

```
┌─ 브라우저 ─┐                    ┌─ 서버 ─┐
│            │ ── 1. 최초 요청 ──→ │        │
│            │                    │        │
│            │ ←── 2. 응답 ────── │        │
│            │   Set-Cookie: id=1 │        │
│  쿠키 저장  │                    │        │
│  id=1      │                    │        │
│            │ ── 3. 재요청 ────→ │        │
│            │   Cookie: id=1     │        │
│            │                    │  사용자 │
│            │ ←── 4. 응답 ────── │  식별!  │
└────────────┘                    └────────┘
```

### 주요 용도

| 용도 | 예시 |
|------|------|
| **세션 관리** | 로그인 상태 유지, 장바구니 |
| **개인화** | 사용자 설정, 테마, 언어 |
| **트래킹** | 사용자 행동 분석, 광고 추적 |

---

## HTTP 헤더로 살펴보는 쿠키

쿠키는 HTTP 헤더를 통해 주고받는다.

### 서버 → 클라이언트 (Set-Cookie)

서버가 응답 헤더에 `Set-Cookie`를 포함하면, 브라우저는 해당 쿠키를 저장한다.

```
HTTP/1.1 200 OK
Set-Cookie: username=홍길동
Set-Cookie: theme=dark; Max-Age=86400; HttpOnly
Content-Type: text/html
```

### 클라이언트 → 서버 (Cookie)

브라우저는 저장된 쿠키를 다음 요청부터 `Cookie` 헤더에 자동으로 포함한다.

```
GET /dashboard HTTP/1.1
Host: example.com
Cookie: username=홍길동; theme=dark
```

> 하나의 `Set-Cookie` 헤더에는 **하나의 쿠키만** 설정할 수 있다. 여러 쿠키를 설정하려면 `Set-Cookie` 헤더를 여러 번 보내야 한다. 반면 `Cookie` 요청 헤더에서는 세미콜론(`;`)으로 구분하여 여러 쿠키를 한 줄에 보낸다.

## 쿠키의 속성

`Set-Cookie` 헤더에 속성을 추가하면 쿠키의 유효 범위, 수명, 보안을 제어할 수 있다.

```
Set-Cookie: name=value; Domain=.example.com; Path=/; Max-Age=3600; HttpOnly; Secure; SameSite=Strict
```

### 수명 관련

| 속성 | 설명 |
|------|------|
| **Expires** | 만료 날짜를 UTC 형식으로 지정 (`Expires=Thu, 01 Jan 2027 00:00:00 GMT`) |
| **Max-Age** | 만료까지의 시간을 **초 단위**로 지정 (`Max-Age=3600` → 1시간) |

- `Expires`와 `Max-Age`가 모두 없으면 → **세션 쿠키** (브라우저 종료 시 삭제)
- 둘 다 있으면 → `Max-Age`가 우선

### 범위 관련

| 속성 | 설명 |
|------|------|
| **Domain** | 쿠키가 전송될 도메인 (`Domain=.example.com` → 서브도메인 포함) |
| **Path** | 쿠키가 전송될 경로 (`Path=/api` → `/api`로 시작하는 경로에만 전송) |

### 보안 관련

| 속성 | 설명 |
|------|------|
| **HttpOnly** | JavaScript(`document.cookie`)로 접근 불가 → XSS 방어 |
| **Secure** | HTTPS 요청에서만 쿠키 전송 |
| **SameSite** | 크로스 사이트 요청 시 쿠키 전송 제어 → CSRF 방어 |

### SameSite 옵션 상세

| 값 | 동작 |
|------|------|
| **Strict** | 같은 사이트 요청에서만 쿠키 전송 (가장 엄격) |
| **Lax** | 일부 크로스 사이트 요청(GET 링크 클릭 등)에서만 쿠키 허용 (기본값) |
| **None** | 모든 크로스 사이트 요청에서 쿠키 전송 (`Secure` 필수) |

## Node.JS에서 쿠키 설정하기

### 쿠키 설정 (Set-Cookie)

```javascript
const http = require('http');

const server = http.createServer((req, res) => {
  res.writeHead(200, {
    'Content-Type': 'text/html; charset=utf-8',
    'Set-Cookie': [
      'username=hong; Path=/; HttpOnly',
      `visit_time=${new Date().toISOString()}; Max-Age=86400`,
    ],
  });
  res.end('<h1>쿠키가 설정되었습니다!</h1>');
});

server.listen(3000, () => {
  console.log('서버 실행 중: http://localhost:3000');
});
```

> `Set-Cookie`에 **배열**을 전달하면 여러 쿠키를 한 번에 설정할 수 있다.

### 쿠키 읽기 (Cookie 파싱)

클라이언트가 보낸 쿠키는 `req.headers.cookie` 문자열에 담겨 있다. `key=value` 쌍이 `; `로 구분되므로, 이를 파싱해야 한다.

```javascript
function parseCookies(cookieHeader) {
  const cookies = {};
  if (!cookieHeader) return cookies;

  cookieHeader.split(';').forEach((pair) => {
    const [key, ...rest] = pair.trim().split('=');
    cookies[key] = decodeURIComponent(rest.join('='));
  });

  return cookies;
}
```

```javascript
const http = require('http');

const server = http.createServer((req, res) => {
  const cookies = parseCookies(req.headers.cookie);
  console.log('받은 쿠키:', cookies);

  res.writeHead(200, { 'Content-Type': 'text/html; charset=utf-8' });
  res.end(`<pre>${JSON.stringify(cookies, null, 2)}</pre>`);
});

server.listen(3000);
```

```bash
# 쿠키를 직접 보내서 테스트
$ curl -b "username=hong; theme=dark" http://localhost:3000
```

```json
{
  "username": "hong",
  "theme": "dark"
}
```

## 실습: 간단한 로그인 상태 유지

쿠키를 사용하여 로그인 여부를 판별하는 예제다.

```javascript
const http = require('http');

function parseCookies(cookieHeader) {
  const cookies = {};
  if (!cookieHeader) return cookies;
  cookieHeader.split(';').forEach((pair) => {
    const [key, ...rest] = pair.trim().split('=');
    cookies[key] = decodeURIComponent(rest.join('='));
  });
  return cookies;
}

const server = http.createServer((req, res) => {
  const cookies = parseCookies(req.headers.cookie);
  const { url, method } = req;

  // 로그인 페이지
  if (url === '/login' && method === 'GET') {
    res.writeHead(200, { 'Content-Type': 'text/html; charset=utf-8' });
    res.end(`
      <form method="POST" action="/login">
        <label>이름: <input name="name" /></label>
        <button type="submit">로그인</button>
      </form>
    `);
    return;
  }

  // 로그인 처리
  if (url === '/login' && method === 'POST') {
    let body = '';
    req.on('data', (chunk) => { body += chunk; });
    req.on('end', () => {
      const params = new URLSearchParams(body);
      const name = params.get('name');

      res.writeHead(302, {
        'Set-Cookie': `user=${encodeURIComponent(name)}; Path=/; HttpOnly; Max-Age=3600`,
        Location: '/',
      });
      res.end();
    });
    return;
  }

  // 로그아웃
  if (url === '/logout') {
    res.writeHead(302, {
      'Set-Cookie': 'user=; Path=/; HttpOnly; Max-Age=0',
      Location: '/',
    });
    res.end();
    return;
  }

  // 홈 페이지
  if (cookies.user) {
    res.writeHead(200, { 'Content-Type': 'text/html; charset=utf-8' });
    res.end(`
      <h1>환영합니다, ${cookies.user}님!</h1>
      <a href="/logout">로그아웃</a>
    `);
  } else {
    res.writeHead(200, { 'Content-Type': 'text/html; charset=utf-8' });
    res.end(`
      <h1>로그인이 필요합니다</h1>
      <a href="/login">로그인 하기</a>
    `);
  }
});

server.listen(3000, () => {
  console.log('로그인 서버: http://localhost:3000');
});
```

```
[로그인 흐름]

GET /login          → 로그인 폼 표시
POST /login         → Set-Cookie: user=홍길동 → 302 → /
GET /  (쿠키 있음)   → "환영합니다, 홍길동님!"
GET /logout         → Set-Cookie: user=; Max-Age=0 → 302 → /
GET /  (쿠키 없음)   → "로그인이 필요합니다"
```

> `Max-Age=0`으로 설정하면 쿠키가 즉시 만료되어 **삭제**된다.

## 쿠키의 한계와 보안 주의사항

### 한계

| 항목 | 내용 |
|------|------|
| **용량 제한** | 쿠키 하나당 약 4KB, 도메인당 약 20~50개 |
| **매 요청마다 전송** | 쿠키 데이터가 클수록 네트워크 트래픽 증가 |
| **문자열만 저장** | 객체를 저장하려면 직렬화 필요 |

### 보안 위험

| 위협 | 설명 | 대응 |
|------|------|------|
| **XSS** | 악성 스크립트가 `document.cookie`로 쿠키 탈취 | `HttpOnly` 속성 |
| **CSRF** | 다른 사이트에서 사용자의 쿠키로 위조 요청 전송 | `SameSite` 속성 |
| **도청** | 평문 HTTP에서 쿠키 내용이 노출 | `Secure` 속성 + HTTPS |
| **변조** | 클라이언트가 쿠키 값을 임의로 수정 | 서버에서 서명(signed cookie) 검증 |

> 쿠키에 **비밀번호, 개인정보 등 민감한 데이터를 직접 저장하면 안 된다**. 대신 서버 측 세션(Session)에 데이터를 저장하고, 쿠키에는 세션 ID만 담는 방식을 사용한다.

## 쿠키 vs 세션 vs 토큰

| 구분 | 쿠키 | 세션 | JWT 토큰 |
|------|------|------|----------|
| **저장 위치** | 클라이언트(브라우저) | 서버(메모리/DB) | 클라이언트 |
| **용량** | ~4KB | 서버 자원에 따라 | ~8KB (페이로드에 따라) |
| **보안** | 변조 가능 | 서버에서 관리 | 서명으로 변조 방지 |
| **확장성** | - | 서버 간 세션 공유 필요 | 서버 간 공유 불필요 |
| **만료** | Expires / Max-Age | 서버에서 제어 | 토큰 내 exp 클레임 |

```
[쿠키 + 세션 방식]

브라우저                서버
  │  POST /login  ───→  │  세션 생성 → 세션 저장소에 { sid: abc, user: '홍길동' }
  │  ←── Set-Cookie ──  │  Set-Cookie: sid=abc; HttpOnly
  │                      │
  │  GET /dashboard ──→  │  Cookie: sid=abc → 세션 조회 → 사용자 확인
  │  ←── 응답 ─────────  │

[JWT 토큰 방식]

브라우저                서버
  │  POST /login  ───→  │  JWT 생성 → { sub: '홍길동', exp: ... } + 서명
  │  ←── 토큰 반환 ────  │
  │                      │
  │  GET /dashboard ──→  │  Authorization: Bearer <token> → 서명 검증
  │  ←── 응답 ─────────  │
```
