> 이전 포스트에서 세션의 보안 주의사항으로 **Secure 쿠키**(HTTPS에서만 전송)를 언급했다. HTTPS가 무엇이고, 왜 필요하며, Node.JS에서 어떻게 구축하는지 알아보자.

## HTTPS란?

HTTPS(HyperText Transfer Protocol **Secure**)는 HTTP에 **SSL/TLS** 암호화 계층을 추가한 프로토콜이다. HTTP가 데이터를 평문(Plain Text)으로 전송하는 반면, HTTPS는 데이터를 **암호화**하여 전송한다.

```
[HTTP — 평문 전송]
브라우저 ──── "password=1234" ────→ 서버
                 ↑
              도청자가 내용을 그대로 볼 수 있다

[HTTPS — 암호화 전송]
브라우저 ──── "x9#kL2$mP..." ────→ 서버
                 ↑
              도청해도 의미를 알 수 없다
```

### HTTP vs HTTPS

| 비교 항목 | HTTP | HTTPS |
|-----------|------|-------|
| **포트** | 80 | 443 |
| **데이터 전송** | 평문 | 암호화 |
| **인증서** | 불필요 | SSL/TLS 인증서 필요 |
| **도청 방어** | 불가 | 가능 |
| **변조 방어** | 불가 | 가능 (무결성 보장) |
| **신원 확인** | 불가 | 가능 (서버 인증) |

## SSL/TLS 기초 개념

### SSL과 TLS

| 용어 | 설명 |
|------|------|
| **SSL** (Secure Sockets Layer) | Netscape가 개발한 초기 암호화 프로토콜. SSL 3.0까지 발전 후 TLS로 전환 |
| **TLS** (Transport Layer Security) | SSL의 후속 표준. 현재 TLS 1.2 / 1.3이 사용됨 |

> 엄밀히 말하면 현재 사용되는 것은 **TLS**이지만, 관습적으로 "SSL 인증서", "SSL/TLS"라는 표현을 혼용한다.

### 암호화 방식

HTTPS는 두 가지 암호화 방식을 조합하여 사용한다.

```
┌─────────── 대칭 키 암호화 ───────────┐
│                                      │
│  같은 키로 암호화 / 복호화            │
│  예: AES                             │
│                                      │
│  장점: 빠르다                         │
│  단점: 키를 안전하게 전달하기 어렵다   │
└──────────────────────────────────────┘

┌─────────── 비대칭 키 암호화 ──────────┐
│                                       │
│  공개 키(Public Key) → 암호화          │
│  비밀 키(Private Key) → 복호화         │
│                                       │
│  장점: 키 전달 문제 해결               │
│  단점: 느리다                          │
└───────────────────────────────────────┘
```

HTTPS는 **비대칭 키**로 대칭 키를 안전하게 교환한 뒤, 이후 통신은 **대칭 키**로 암호화하여 속도와 보안을 모두 확보한다.

## TLS 핸드셰이크

클라이언트와 서버가 HTTPS 연결을 수립하는 과정을 **TLS 핸드셰이크**라 한다.

```
브라우저(클라이언트)                              서버
  │                                              │
  │ ── 1. ClientHello ─────────────────────────→ │
  │    (지원하는 TLS 버전, 암호 스위트 목록)       │
  │                                              │
  │ ←── 2. ServerHello ──────────────────────── │
  │    (선택된 TLS 버전, 암호 스위트)              │
  │                                              │
  │ ←── 3. 인증서 전송 ─────────────────────── │
  │    (서버의 SSL/TLS 인증서 + 공개 키)          │
  │                                              │
  │  4. 인증서 검증                               │
  │     CA의 서명 확인                            │
  │     도메인 일치 여부 확인                      │
  │                                              │
  │ ── 5. 대칭 키 교환 ────────────────────────→ │
  │    (공개 키로 암호화된 Pre-Master Secret)      │
  │                                              │
  │  6. 양쪽 모두 동일한 대칭 키(세션 키) 생성     │
  │                                              │
  │ ←══════════ 암호화된 통신 시작 ════════════→ │
```

### 핸드셰이크 핵심 정리

| 단계 | 목적 |
|------|------|
| **ClientHello / ServerHello** | 사용할 암호화 방식 합의 |
| **인증서 전송** | 서버의 신원을 증명 |
| **인증서 검증** | 클라이언트가 서버를 신뢰할 수 있는지 확인 |
| **키 교환** | 이후 통신에 사용할 대칭 키를 안전하게 공유 |

## SSL/TLS 인증서

### 인증서의 역할

SSL/TLS 인증서는 세 가지 역할을 한다.

1. **서버 인증**: 이 서버가 진짜 해당 도메인의 소유자인지 증명
2. **공개 키 배포**: 암호화에 사용할 공개 키를 클라이언트에 전달
3. **무결성 보장**: 인증 기관(CA)의 서명으로 인증서 변조 방지

### 인증 기관 (CA)

```
┌───── 인증서 발급 체계 ─────────────────────────┐
│                                                │
│  Root CA (최상위 인증 기관)                      │
│    │  DigiCert, Let's Encrypt 등                │
│    │                                            │
│    └─→ Intermediate CA (중간 인증 기관)          │
│          │                                      │
│          └─→ 서버 인증서 (example.com)           │
│                                                │
│  브라우저는 Root CA 목록을 내장하고 있어          │
│  인증서 체인을 따라 올라가며 신뢰 여부를 판단     │
└────────────────────────────────────────────────┘
```

### 인증서 종류

| 종류 | 검증 수준 | 용도 |
|------|-----------|------|
| **DV** (Domain Validation) | 도메인 소유권만 확인 | 개인 사이트, 소규모 서비스 |
| **OV** (Organization Validation) | 조직 실체까지 확인 | 기업 웹사이트 |
| **EV** (Extended Validation) | 엄격한 조직 심사 | 금융, 전자상거래 |

## Node.JS에서 HTTPS 서버 만들기

Node.JS는 `https` 내장 모듈로 HTTPS 서버를 만들 수 있다. `http` 모듈과 거의 동일한 API를 가지며, 인증서를 추가로 제공하면 된다.

### 1단계: 자체 서명 인증서 생성 (개발용)

개발 환경에서는 **자체 서명(Self-signed) 인증서**를 사용한다. OpenSSL로 생성할 수 있다.

```bash
# 비밀 키 생성
$ openssl genrsa -out private-key.pem 2048

# 인증서 서명 요청(CSR) 생성
$ openssl req -new -key private-key.pem -out csr.pem

# 자체 서명 인증서 생성 (365일 유효)
$ openssl x509 -req -in csr.pem -signkey private-key.pem -out certificate.pem -days 365
```

또는 한 줄로 비밀 키와 인증서를 동시에 생성할 수 있다.

```bash
$ openssl req -x509 -newkey rsa:2048 -keyout private-key.pem -out certificate.pem -days 365 -nodes -subj "/CN=localhost"
```

```
생성된 파일:

project/
├── private-key.pem    ← 비밀 키 (절대 공개하면 안 됨!)
├── certificate.pem    ← 인증서 (공개 키 포함)
└── server.js
```

> 자체 서명 인증서는 CA가 서명한 것이 아니므로 브라우저에서 **"이 연결은 안전하지 않습니다"** 경고가 표시된다. 개발 환경에서만 사용해야 한다.

### 2단계: HTTPS 서버 코드

```javascript
const https = require('https');
const fs = require('fs');

const options = {
  key: fs.readFileSync('private-key.pem'),
  cert: fs.readFileSync('certificate.pem'),
};

const server = https.createServer(options, (req, res) => {
  res.writeHead(200, { 'Content-Type': 'text/html; charset=utf-8' });
  res.end('<h1>HTTPS 서버에 오신 것을 환영합니다!</h1>');
});

server.listen(443, () => {
  console.log('HTTPS 서버: https://localhost');
});
```

> `http.createServer(callback)`과 달리 `https.createServer(options, callback)` 형태로, 첫 번째 인자에 인증서 옵션을 전달한다.

### http 모듈과의 비교

```javascript
// HTTP 서버
const http = require('http');
http.createServer((req, res) => { ... }).listen(80);

// HTTPS 서버 — 인증서 옵션만 추가하면 된다
const https = require('https');
const options = { key: ..., cert: ... };
https.createServer(options, (req, res) => { ... }).listen(443);
```

## HTTP → HTTPS 리다이렉트

실서비스에서는 HTTP(80)로 들어온 요청을 HTTPS(443)로 자동 리다이렉트해야 한다.

```javascript
const http = require('http');
const https = require('https');
const fs = require('fs');

const options = {
  key: fs.readFileSync('private-key.pem'),
  cert: fs.readFileSync('certificate.pem'),
};

// HTTPS 서버 (메인)
https.createServer(options, (req, res) => {
  res.writeHead(200, { 'Content-Type': 'text/html; charset=utf-8' });
  res.end('<h1>안전한 HTTPS 연결입니다!</h1>');
}).listen(443, () => {
  console.log('HTTPS 서버: https://localhost');
});

// HTTP 서버 (리다이렉트 전용)
http.createServer((req, res) => {
  res.writeHead(301, {
    Location: `https://${req.headers.host}${req.url}`,
  });
  res.end();
}).listen(80, () => {
  console.log('HTTP → HTTPS 리다이렉트 활성화');
});
```

```
[리다이렉트 흐름]

브라우저                    HTTP 서버 (:80)           HTTPS 서버 (:443)
  │  GET http://ex.com →  │                         │
  │  ←── 301 Moved        │                         │
  │      Location:        │                         │
  │      https://ex.com   │                         │
  │                       │                         │
  │  GET https://ex.com ─────────────────────────→  │
  │  ←── 200 OK (암호화) ──────────────────────── │
```

## 실습: 세션 + HTTPS 보안 서버

이전 포스트의 세션 서버를 HTTPS로 업그레이드하면, **Secure 쿠키**를 안전하게 사용할 수 있다.

```javascript
const https = require('https');
const http = require('http');
const fs = require('fs');
const crypto = require('crypto');

const options = {
  key: fs.readFileSync('private-key.pem'),
  cert: fs.readFileSync('certificate.pem'),
};

function parseCookies(cookieHeader) {
  const cookies = {};
  if (!cookieHeader) return cookies;
  cookieHeader.split(';').forEach((pair) => {
    const [key, ...rest] = pair.trim().split('=');
    cookies[key] = decodeURIComponent(rest.join('='));
  });
  return cookies;
}

function generateSessionId() {
  return crypto.randomBytes(32).toString('hex');
}

const sessions = {};

const app = (req, res) => {
  const cookies = parseCookies(req.headers.cookie);
  const { url, method } = req;

  if (url === '/login' && method === 'GET') {
    res.writeHead(200, { 'Content-Type': 'text/html; charset=utf-8' });
    res.end(`
      <form method="POST" action="/login">
        <label>이름: <input name="name" /></label>
        <button type="submit">로그인</button>
      </form>
    `);
    return;
  }

  if (url === '/login' && method === 'POST') {
    let body = '';
    req.on('data', (chunk) => { body += chunk; });
    req.on('end', () => {
      const params = new URLSearchParams(body);
      const name = params.get('name');

      const sid = generateSessionId();
      sessions[sid] = { user: name, createdAt: Date.now() };

      res.writeHead(302, {
        'Set-Cookie': `sid=${sid}; Path=/; HttpOnly; Secure; SameSite=Strict`,
        Location: '/',
      });
      res.end();
    });
    return;
  }

  if (url === '/logout') {
    if (cookies.sid) delete sessions[cookies.sid];
    res.writeHead(302, {
      'Set-Cookie': 'sid=; Path=/; HttpOnly; Secure; Max-Age=0',
      Location: '/',
    });
    res.end();
    return;
  }

  const session = sessions[cookies.sid];
  res.writeHead(200, { 'Content-Type': 'text/html; charset=utf-8' });

  if (session) {
    res.end(`
      <h1>🔒 안전한 연결: 환영합니다, ${session.user}님!</h1>
      <p>프로토콜: HTTPS</p>
      <a href="/logout">로그아웃</a>
    `);
  } else {
    res.end(`
      <h1>로그인이 필요합니다</h1>
      <a href="/login">로그인 하기</a>
    `);
  }
};

https.createServer(options, app).listen(443, () => {
  console.log('HTTPS 세션 서버: https://localhost');
});

http.createServer((req, res) => {
  res.writeHead(301, { Location: `https://${req.headers.host}${req.url}` });
  res.end();
}).listen(80);
```

### 이전 세션 서버와의 차이

| 변경 사항 | 설명 |
|-----------|------|
| `https.createServer` | HTTP → HTTPS로 전환 |
| `Secure` 쿠키 속성 추가 | HTTPS 연결에서만 쿠키 전송 |
| `SameSite=Strict` 추가 | CSRF 공격 방어 |
| HTTP 리다이렉트 서버 추가 | 80포트 접속 시 HTTPS로 자동 전환 |

> 이전 세션 포스트에서 `secure: false`로 설정했던 이유가 바로 HTTPS가 아닌 개발 환경이었기 때문이다. HTTPS를 적용하면 `Secure` 속성을 `true`로 설정하여 쿠키가 암호화된 연결에서만 전송되도록 해야 한다.

## Let's Encrypt (무료 SSL 인증서)

프로덕션 환경에서는 자체 서명 인증서 대신 **CA가 발급한 인증서**를 사용해야 한다. **Let's Encrypt**는 무료로 SSL/TLS 인증서를 발급해주는 CA이다.

### Certbot으로 인증서 발급

```bash
# Certbot 설치 (Ubuntu)
$ sudo apt install certbot

# 인증서 발급 (도메인 소유권 검증)
$ sudo certbot certonly --standalone -d example.com

# 발급된 인증서 위치
# /etc/letsencrypt/live/example.com/fullchain.pem  ← 인증서
# /etc/letsencrypt/live/example.com/privkey.pem    ← 비밀 키
```

```javascript
const https = require('https');
const fs = require('fs');

const options = {
  key: fs.readFileSync('/etc/letsencrypt/live/example.com/privkey.pem'),
  cert: fs.readFileSync('/etc/letsencrypt/live/example.com/fullchain.pem'),
};

https.createServer(options, (req, res) => {
  res.writeHead(200, { 'Content-Type': 'text/html; charset=utf-8' });
  res.end('<h1>Let\'s Encrypt HTTPS 서버!</h1>');
}).listen(443);
```

### Let's Encrypt 특징

| 항목 | 내용 |
|------|------|
| **비용** | 무료 |
| **인증서 유형** | DV (Domain Validation) |
| **유효 기간** | 90일 (자동 갱신 권장) |
| **자동 갱신** | `certbot renew` 명령으로 가능 |
| **와일드카드** | `*.example.com` 지원 (DNS 검증 필요) |

```bash
# 자동 갱신 설정 (cron)
$ sudo crontab -e
0 0 1 * * certbot renew --quiet && systemctl reload nginx
```

## HTTPS 주요 옵션

`https.createServer()`에 전달할 수 있는 주요 TLS 옵션을 정리한다.

```javascript
const options = {
  key: fs.readFileSync('private-key.pem'),       // 비밀 키
  cert: fs.readFileSync('certificate.pem'),      // 인증서
  ca: fs.readFileSync('ca-certificate.pem'),     // CA 인증서 (체인)
  passphrase: 'my-passphrase',                   // 비밀 키 암호 (있는 경우)

  // 보안 강화 옵션
  minVersion: 'TLSv1.2',                         // 최소 TLS 버전
  ciphers: 'ECDHE-RSA-AES128-GCM-SHA256',        // 암호 스위트 지정
};
```

| 옵션 | 설명 |
|------|------|
| **key** | 서버 비밀 키 파일 |
| **cert** | 서버 인증서 파일 |
| **ca** | CA 인증서 (중간 인증서 포함 시 사용) |
| **passphrase** | 비밀 키가 암호화된 경우 해독 암호 |
| **minVersion** | 허용할 최소 TLS 버전 (보안 위해 TLSv1.2 이상 권장) |
| **ciphers** | 사용할 암호 스위트 목록 |

## 실무에서의 HTTPS

실제 프로덕션 환경에서는 Node.JS가 직접 HTTPS를 처리하기보다, **리버스 프록시** 뒤에서 동작하는 것이 일반적이다.

```
┌── 클라이언트 ──┐
│                │
│  HTTPS 요청    │
└───────┬────────┘
        │
        ▼
┌── Nginx / ALB ──────────┐
│  SSL/TLS 종료 (Termination) │
│  인증서 관리                  │
│  로드 밸런싱                  │
└───────┬─────────────────┘
        │  HTTP (내부 네트워크)
        ▼
┌── Node.JS 서버 ──┐
│  app.listen(3000) │
│  비즈니스 로직     │
└──────────────────┘
```

### SSL Termination

| 방식 | 설명 |
|------|------|
| **Nginx에서 SSL 종료** | Nginx가 HTTPS를 처리하고, 내부에서는 HTTP로 Node.JS와 통신 |
| **Node.JS에서 직접 처리** | 소규모 서비스나 개발 환경에서 사용 |
| **클라우드 로드 밸런서** | AWS ALB, GCP LB 등에서 SSL 인증서 관리 |

```nginx
# Nginx SSL 설정 예시
server {
    listen 443 ssl;
    server_name example.com;

    ssl_certificate     /etc/letsencrypt/live/example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/example.com/privkey.pem;
    ssl_protocols       TLSv1.2 TLSv1.3;

    location / {
        proxy_pass http://localhost:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

server {
    listen 80;
```

> Nginx 뒤에서 동작할 때 `X-Forwarded-Proto` 헤더를 통해 원래 요청이 HTTPS였는지 확인할 수 있다. Express에서는 `app.set('trust proxy', 1)`을 설정하면 `req.secure`로 확인 가능하다.
